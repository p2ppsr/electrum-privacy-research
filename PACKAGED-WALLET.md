# Official macOS distribution capture

The official [ElectrumSVP 0.2.0 release](https://github.com/TruthMachine/ElectrumSVP/releases/tag/v0.2.0) DMG is 193,526,058 bytes, SHA-256 `657a1eaaafb40ea5f3db7b3c21ecd93e7c1c8b03d6de570e8f10bbb187a05f47`. Both the checksum-file signature and the detached DMG signature verified against the publisher's published key fingerprint `E9BAFA19B15E6C2C158CDD400DB16C74A9CA7CF6`. [Verification receipts](evidence/publication-20261029/). This establishes consistency with that published key, not an independently verified legal identity. Gatekeeper reports no usable Apple signature; no OS trust protection was globally disabled.

The package contains Intel Python **3.9.13**. The operator explicitly authorized installing Rosetta 2 and accepting Apple's license; [installation output](evidence/publication-20261029/rosetta-install.log) is retained. The host was arm64 macOS 27.0.1 (26A434). All **145 shared Python modules have identical parsed code** to release tag `672df8f4512f6adf16a3c99146baa6be9b93d86f`; byte differences are formatting. [Module comparison](evidence/packaged-wallet-20261029/python-module-comparison.json), [key module hashes, pool extraction and diffs](evidence/packaged-wallet-20261029/source-comparison.json). This is not reproducible-build attestation of every native library or packaged resource.

## Desktop session with network settings unset

A new disposable standard wallet was created using the bundled wallet APIs and opened through the desktop GUI. No existing personal wallet or mainnet funds were used. No server, auto-connect, one-server or proxy setting was supplied. The GUI visibly showed automatic selection enabled and proxy use disabled.

The [recorded GUI run](evidence/packaged-gui-attempt-01/result.json) completed **40 distinct script-hash subscriptions** to `sv2.electrumr.sv`. Seven core hosts completed RPCs. Seven helper hosts received successful TLS sends containing a block-height lookup. The union was eight Electrum hostnames, including helper-only `sv3.satoshi.io`; no financial helper lookup occurred in this empty-wallet run. The network overview visibly showed seven connected core servers at height 973225. DNS audit also observed `electrumsv.io` and `bananablocks.com`, the update and rate-service names. Their generic requests are not evidence that either received the wallet identifier collection.

[GUI RPC observations](evidence/packaged-gui-attempt-01/gui-rpc-events.jsonl) · [socket/DNS audit](evidence/packaged-gui-attempt-01/socket-audit.jsonl) · [network overview](evidence/packaged-gui-attempt-01/network-overview.png) · [server defaults](evidence/packaged-gui-attempt-01/network-server.png) · [proxy defaults](evidence/packaged-gui-attempt-01/network-proxy.png) · [connected zero-balance dashboard](evidence/packaged-gui-attempt-01/dashboard.png).

These are client-side completions/send observations, not public-server internal logs. The separate [bundled-core capture](evidence/packaged-core-attempt-01/run.json) ran the same distribution's interpreter and wallet modules behind a server-side recording TLS frontend. It retained the 40 identifiers and relayed them to `sv.electrumr.sv`. That run explicitly pinned a local main server and one-server mode and used headless callbacks. It is not a default GUI routing run. Together the experiments distinguish the desktop defaults from what a receiving frontend can record.

## Explicit isolation and observation controls

The vendor CFBundle shell wrapper discards supplied arguments. The package's `main.py` also writes `~/.electrum-sv/headers` before reading `-D`. To protect this computer's real wallets, a lab app wrapper invokes an identical copied bundled interpreter, loading unedited vendor modules from the read-only mounted DMG. Its bundle name/identifier and launch wrapper were changed. The [bootstrap](privacy_lab/packaged_bootstrap.py) redirects Python home-path resolution and legacy wallet paths, supplies private `-D` and the disposable wallet path, blocks access to existing wallet/node directories, and records socket/RPC metadata. It does not change the process HOME environment variable, network settings, server lists or TLS acceptance behavior.

Initial launches used an OS filesystem sandbox; later GUI launches used the explicit audit guard and isolated paths while resolving app identification. Failed CPU, library-path, path-isolation and stale-daemon attempts are retained. The computer-control tool initially could not identify the Qt app; the operator brought it forward, after which screenshots and actions used that tool. No seed/private-key page was opened or captured. The test wallet's existing password was entered only to open it. The final GUI exited normally; ignored wallet state and temporary app copies are removed during closeout.
